# 神奇的 `sql` 运算符 🪄

在使用 ORM 库时，可能会遇到这样一些情况：你发现使用所提供的 ORM 语法很难编写某个特定查询。在这种情况下，你可以转而使用原始查询，也就是将查询构造成一个原始字符串。然而，原始查询往往缺乏类型安全和查询参数化带来的优势。

为了解决这个问题，许多库引入了 `sql` 模板的概念。这个模板允许你编写更具类型安全且参数化的查询，从而提升代码整体的安全性和灵活性。Drizzle 作为一个强大的 ORM 库，同样支持 sql 模板。

借助 Drizzle 的 `sql` 模板，你甚至可以在查询编写上更进一步。如果你在使用该库的查询构建器编写完整查询时遇到困难，可以在 Drizzle 查询的特定部分中选择性地使用 `sql` 模板。这种灵活性使你能够在部分 SELECT 语句、WHERE 子句、ORDER BY 子句、HAVING 子句、GROUP BY 子句，甚至关系查询构建器中使用 sql 模板。

通过利用 Drizzle 中 sql 模板的能力，你可以在保持类型安全和查询参数化优势的同时，实现所需的查询结构和复杂度。这将使你能够在应用程序中创建更健壮、更易维护的代码。

## sql`` 模板

你可能在其他 ORM 中也会遇到的一种最常见用法，  
就是能够原样使用 `sql` 查询来执行原始查询。

```typescript copy
import { sql } from 'drizzle-orm' 

const id = 69;
await db.execute(sql`select * from ${usersTable} where ${usersTable.id} = ${id}`)
```

它将生成当前查询

```sql
select * from `users` where `users`.`id` = ?; --> [69]
```

提供给 sql 参数的任何表和列都会自动映射为其对应的 SQL  
语法：表名会进行转义，且转义后的表名会附加到列名上。 

此外，任何动态参数，例如 `${id}`，都会被映射为 `?` 占位符，  
并且对应的值会被移动到一个单独的值数组中，然后再传递给数据库。 

这种方式可以有效防止任何潜在的 SQL 注入漏洞。

## `sql<T>`

<Callout type="info" emoji="ℹ️">
    请注意，`sql<T>` 不会执行任何运行时映射。你使用 `sql<T>` 定义的类型
    仅仅是 Drizzle 的一个辅助工具。需要理解的是，由于 SQL 查询可能非常灵活且可定制，
    因此没有可行的方法能够动态确定精确的类型。 
</Callout>

你可以在 Drizzle 中定义一个自定义类型，用于字段需要除 `unknown` 之外的特定类型的场景。

此功能在部分选择查询中特别有用，可确保所选字段的类型保持一致：

```typescript
// 未定义 sql<T> 类型
const response: { lowerName: unknown }[] = await db.select({
    lowerName: sql`lower(${usersTable.id})`
}).from(usersTable);

// 定义了 sql<T> 类型
const response: { lowerName: string }[] = await db.select({
    lowerName: sql<string>`lower(${usersTable.id})`
}).from(usersTable);
```

## `sql``.mapWith()`

对于需要在运行时将数据库驱动传递给 drizzle 的值进行映射的场景，你可以使用 `.mapWith()`

这个函数接受不同的值，这些值会在运行时映射响应。

只要 mapWith 内部的接口与 Column 实现的接口相同，你就可以复刻特定的列映射策略。

```typescript
import { singlestoreTable, int, text } from 'drizzle-orm/singlestore-core';

const usersTable = singlestoreTable('users', {
    id: int('id').primaryKey().autoincrement(),
    name: text('name').notNull(),
});

//  在运行时，这些值会像 drizzle 中 `text` 列的映射方式一样被映射
sql`...`.mapWith(usersTable.name);
```

你也可以传入 `DriverValueDecoder` 接口的自定义实现：

```ts 
sql``.mapWith({
	mapFromDriverValue: (value: any) => {
		const mappedValue = value;
		// 你想应用的映射
		return mappedValue;
	},
});
    
// 或者
sql``.mapWith(Number);
```

## `sql``.as<T>()`

在不同情况下，有时可能很难确定要如何命名你想使用的自定义字段。
你可能会遇到需要为一个将被选取的字段显式指定别名的情况。这在处理复杂查询时尤其有用。 

为了解决这些场景，我们引入了一个有用的 `.as('alias_name')` 辅助方法，它允许
你显式地定义别名。通过利用这个特性，你可以为该字段提供一个清晰且有意义的
名称，使你的查询更直观且更易读。

<Section>
```typescript
sql`lower(usersTable.name)`.as('lower_name')
```
```sql
... `usersTable`.`name` as lower_name ...
```
</Section>

## `sql.raw()`

在某些情况下，你可能不需要根据输入创建参数化值，也不需要将表/列映射为转义后的值。  
相反，你可能只是希望按原样生成查询。对于这种情况，我们提供了 `sql.raw()` 函数。

`sql.raw()` 函数允许你在查询中包含原始 SQL 语句，而无需进行任何额外处理或转义。  
当你已经预先构造好 SQL 语句，或者需要将复杂或动态的 SQL 代码直接纳入查询时，这会非常有用。

<Section>
```typescript
sql.raw(`select * from users where id = ${12}`);
// vs
sql`select * from users where id = ${12}`;
```
```sql
select * from users where id = 12;
--> vs
select * from users where id = ?; --> [12]
```
</Section>

你还可以在 sql 函数中使用 `sql.raw()`，从而能够包含任何原始字符串，而无需通过主 `sql` 模板函数对其进行转义。

通过在 `sql` 函数中使用 `sql.raw()`，你可以将未转义的原始字符串直接纳入查询中。  
当你有某些特定的 SQL 代码或表达式需要保持原样，不受模板函数自动转义或修改影响时，这尤其有用。

<Section>
```typescript
sql`select * from ${usersTable} where id = ${12}`;
// vs
sql`select * from ${usersTable} where id = ${sql.raw(12)}`;
```
```sql
select * from `users` where id = ?; --> [12]
--> vs
select * from `users` where id = 12;
```
</Section>

## sql.fromList()

`sql` 模板会生成 sql 片段，这些片段是 SQL 部分的数组，在将 SQL 应用于 Drizzle 中的数据库或查询后，会被拼接到查询和参数中。

在某些场景下，你可能需要使用自定义业务逻辑将这些片段聚合到一个数组中，然后将它们拼接成一个可以传递给数据库或查询的单个 SQL 语句。
对于这些情况，fromList 函数会非常有用。

fromList 函数允许你将多个 SQL 片段组合成一个单一的 SQL 语句。
你可以用它按照你的特定需求聚合并拼接各个 SQL 部分，然后得到一个可以执行的统一 SQL 查询。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// some logic

sqlChunks.push(sql` where `);

// some logic

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

	if (i === 4) continue;
	sqlChunks.push(sql` or `);
}

const finalSql: SQL = sql.fromList(sqlChunks)
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.join()

实际上，`sql.join` 函数与 fromList 辅助函数具有类似的用途。 
然而，在处理 SQL 片段之间的空格，或者为连接 SQL 片段指定自定义分隔符时，它提供了额外的灵活性。

使用 `sql.join`，你可以使用指定的分隔符将 SQL 片段连接在一起。 
这个分隔符可以是你想要插入到这些片段之间的任意字符串或字符。 

当你对 SQL 片段的格式化或分隔有特定要求时，这尤其有用。通过指定自定义分隔符，你可以在最终的 SQL 查询中实现所需的结构和格式。

<Section>
```typescript
const sqlChunks: SQL[] = [];

sqlChunks.push(sql`select * from users`);

// 一些逻辑

sqlChunks.push(sql`where`);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	sqlChunks.push(sql`id = ${i}`);

if (i === 4) continue;
    sqlChunks.push(sql`or`);
}

const finalSql: SQL = sql.join(sqlChunks, sql.raw(' '));
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.append()

如果你已经使用 `sql` 模板生成了 SQL，你可以通过使用 append 函数直接向已生成的 SQL 中添加一个新的块，从而实现与 `fromList` 相同的行为。

通过使用 append 函数，你可以动态地向现有的 SQL 字符串中添加额外的 SQL 块，
从而有效地将它们连接在一起。这使你能够加入自定义逻辑或业务
规则，用于将这些块聚合到最终的 SQL 查询中。

<Section>
```typescript 
const finalSql = sql`select * from users`;

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```
</Section>

## sql.empty()

通过使用 sql.empty()，你可以先创建一个空白的 SQL 对象，然后根据需要动态地向其中追加 SQL 片段。这使你能够逐步构建 SQL 查询，并通过自定义逻辑或条件来决定每个片段的内容。

一旦你使用 sql.empty() 初始化了 SQL 对象，就可以充分利用 sql 模板的完整功能，例如参数化、组合和转义。  
这使你能够以灵活且可控的方式构建 SQL 查询，  
以适应你的特定需求。

```typescript 
const finalSql = sql.empty();

// 一些逻辑

finalSql.append(sql`select * from users`);

// 一些逻辑

finalSql.append(sql` where `);

// 一些逻辑

for (let i = 0; i < 5; i++) {
	finalSql.append(sql`id = ${i}`);

	if (i === 4) continue;
	finalSql.append(sql` or `);
}
```
```sql
select * from users where id = ? or id = ? or id = ? or id = ? or id = ?; --> [0, 1, 2, 3, 4]
```

## `sql` select

你也可以在部分 select 查询中使用 sql 功能。部分 select 查询允许你从表中检索特定字段或列，而不是获取整行。

有关部分 select 查询的更详细信息，你可以参考 Core API 文档中的 **[Core API docs](/docs/singlestore/select#basic-and-partial-select)**。

**从表中选择不同的自定义字段**

这里你可以看到 **[`sql<T>`](/docs/singlestore/sql#sqlt)**、**[`sql``.mapWith()`](/docs/singlestore/sql#sqlmapwith)**、**[`sql``.as<T>()`](/docs/singlestore/sql#sqlast)** 的用法。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

await db.select({
    id: usersTable.id,
    lowerName: sql<string>`lower(${usersTable.name})`,
    aliasedName: sql<string>`lower(${usersTable.name})`.as('aliased_column'),
    count: sql<number>`count(*)`.mapWith(Number) 
}).from(usersTable)
```
```sql
select `id`, lower(`name`), lower(`name`) as `aliased_column`, count(*) from `users`;
```
</Section>

## `sql` 中的 where

确实，Drizzle 提供了一组可在 sql 模板中使用的可用表达式。  
然而，数据库通常还支持更广泛的表达式，  
包括通过扩展或其他方式提供的表达式。

为了确保灵活性，并让你能够使用 Drizzle 原生  
不支持的任何表达式，你可以自由地直接使用 sql 函数编写 SQL 模板。  
这样你就可以充分利用 SQL 的强大功能，并结合目标数据库特有的任何表达式或功能。

通过使用 sql 模板，你不再只受限于 Drizzle 中预定义的表达式。  
相反，你可以表达复杂查询，并结合底层数据库系统提供的任何受支持表达式。

**使用 sql 按 `id` 过滤**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

const id = 77

await db.select()
        .from(usersTable)
        .where(sql`${usersTable.id} = ${id}`)
```
```sql
select * from `users` where `users`.`id` = ?; --> [ 77 ]
```
</Section>

**高级全文搜索 where 语句**
<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

const searchPattern = "%Ale%"

await db.select()
        .from(usersTable)
        .where(sql`lower(${usersTable.name}) like lower(${searchPattern})`)
```
```sql
select * from `users` where lower(`users`.`name`) like lower(?); --> [ "%Ale%" ]
```
</Section>

## `sql` 在 orderBy 中

当你需要 Drizzle 中没有提供的特定排序功能，但又不想直接使用原始 SQL 时，`sql` 模板确实可以用于 ORDER BY 子句。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

await db.select().from(usersTable).orderBy(sql`${usersTable.id} desc nulls first`)
```
```sql
select * from `users` order by `users`.`id` desc nulls first;
```
</Section>

## `sql` 在 having 和 groupBy 中

当你需要某些 Drizzle 中不提供的特定排序功能，但又不想退回到原始 SQL 时，`sql` 模板确实可以用于 HAVING 和 GROUP BY 子句。

<Section>
```typescript copy
import { sql } from 'drizzle-orm'
import { usersTable } from 'schema'

await db.select({ 
    projectId: usersTable.projectId,
    count: sql<number>`count(${usersTable.id})`.mapWith(Number)
}).from(usersTable)
    .groupBy(sql`${usersTable.projectId}`)
    .having(sql`count(${usersTable.id}) > 300`)
```
```sql
select `project_id`, count(`users`.`id`) from users group by `users`.`project_id` having count(`users`.`id`) > 300; 
```
</Section>
