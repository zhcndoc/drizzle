# Drizzle ORM

Drizzle ORM 是一个有头脑的无头 TypeScript ORM。🐲
> Drizzle 就像一位好朋友：在你需要时会陪伴你，在你想要些空间时又不会来打扰你。

它看起来和用起来都很简单，在你的项目进行到第 _1000_ 天时依然表现出色，\
让你按自己的方式做事，并在你需要时始终存在。

**它是唯一同时提供 [关系型](/docs/mssql/rqb) 和 [类 SQL](/docs/mssql/select) 查询 API 的 ORM**， 
在访问关系数据时为你带来两全其美的体验。 
Drizzle 轻量、高性能、类型安全、不含乳糖、不含麸质、清醒、灵活，并且**从设计上就支持 serverless**。
Drizzle 不只是一个库，它是一种体验。🤩

[![Drizzle bestofjs](@/assets/images/bestofjs.jpg)](https://bestofjs.org/projects/drizzle-orm)

## 无头 ORM? 
首先，Drizzle 是一个库，以及一组可互补的按需启用工具。 

**ORM** 代表 _对象关系映射_，开发者往往会把类 Django 或类 Spring 的工具称为 ORM。 
我们真心认为这是一种基于遗留命名法的误解，我们把它们称为 **数据框架**。

<Callout type="error" emoji="️💔">
  使用数据框架时，你必须围绕它们来构建项目，而不是与它们一起构建。
</Callout>

**Drizzle** 让你按照自己想要的方式构建项目，而不会干扰你的项目或项目结构。 

使用 Drizzle，你可以在 TypeScript 中定义和管理数据库 schema，以类似 SQL 或关系型的方式访问数据，并利用按需启用的工具 
将你的开发体验 _提升到极致_。 🤯 

## 为什么像 SQL？
**如果你会 SQL，你就会用 Drizzle。**

其他 ORM 和数据框架往往会偏离 SQL，或者把你与 SQL 抽象隔离开来，这
会导致双重学习成本：既要懂 SQL，又要懂框架的 API。  

Drizzle 恰恰相反。 
我们拥抱 SQL，并将 Drizzle 构建为以 SQL 风格为核心，因此你几乎不需要
学习成本，就能访问 SQL 的全部能力。  

我们带来了所有熟悉的 **[SQL schema](/docs/mssql/sql-schema-declaration)**、**[查询](/docs/mssql/select)**、 
**[自动迁移](/docs/mssql/migrations)** 以及 **[还有一件事](/docs/mssql/rqb)**。 ✨

<CodeTabs items={["index.ts", "schema.ts", "migration.sql"]}>
```typescript copy
// 访问你的数据
await db
	.select()
	.from(countries)
	.leftJoin(cities, eq(cities.countryId, countries.id))
	.where(eq(countries.id, 10))
```
```typescript copy
// 管理你的 schema
export const countries = mssqlTable('countries', {
  id: int().primaryKey().identity(),
  name: varchar({ length: 256 }),
});

export const cities = mssqlTable('cities', {
  id: int().primaryKey().identity(),
  name: varchar({ length: 256 }),
  countryId: int('country_id').references(() => countries.id),
});
```
```sql
CREATE TABLE [countries] (
	[id] int IDENTITY(1, 1),
	[name] varchar(256),
	CONSTRAINT [countries_pkey] PRIMARY KEY([id])
);

CREATE TABLE [cities] (
	[id] int IDENTITY(1, 1),
	[name] varchar(256),
	[country_id] int,
	CONSTRAINT [cities_pkey] PRIMARY KEY([id])
);

ALTER TABLE [cities] ADD CONSTRAINT [cities_country_id_countries_id_fk] FOREIGN KEY ([country_id]) REFERENCES [countries]([id]);
```
</CodeTabs>

## 为什么不是类似 SQL 的方式？
我们始终在努力寻找一个完美平衡的解决方案，虽然类似 SQL 的方式确实能满足 100% 的需求，  
但在某些常见场景下，你可以用一种更好的方式查询数据。  

我们已经为你构建了 **[Queries API](/docs/mssql/rqb)**，因此你可以以最便捷、最高性能的方式从数据库中获取关系型嵌套数据，  
并且再也不用考虑联表和数据映射的问题。  

**Drizzle 始终只输出 точно 1 条 SQL 查询。** 你可以放心地在无服务器数据库中使用它，再也不用担心性能或往返成本！

```ts
const result = await db._query.users.findMany({
	with: {
		posts: true
	},
});
```

## 无服务器？
<Callout type="info" emoji="🥳">
  最棒的部分就是没有多余的部分。**Drizzle 恰好没有任何依赖！**
</Callout>


![Drizzle is slim an Serverless ready](@/assets/images/drizzle31kb.jpg)
  
Drizzle ORM 采用特定方言，轻量、高性能，并且**从设计上**就支持无服务器。  

我们花了很多时间确保你能获得一流的 SQL 方言支持，包括 Postgres、MySQL 以及其他数据库。

Drizzle 通过行业标准的数据库驱动程序原生运行。我们支持市面上所有主流的 **[PostgreSQL](/docs/get-started-postgresql)**、**[MySQL](/docs/mysql/get-started-mysql)**、**[SQLite](/docs/sqlite/get-started-sqlite)**、**[SingleStore](/docs/singlestore/get-started-singlestore)**、**[MSSQL](/docs/mssql/get-started-mssql)** 或 **[CockroachDB](/docs/cockroach/get-started-cockroach)** 驱动程序，并且我们还在**[飞速](https://twitter.com/DrizzleORM/status/1653082492742647811?s=20)**添加新的驱动程序。
