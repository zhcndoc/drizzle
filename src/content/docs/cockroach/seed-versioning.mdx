# 版本管理

`drizzle-seed` 使用版本管理来处理静态数据和动态数据的输出。为了确保真正的确定性，请确保在使用相同的 `seed` 数字时，值保持不变。如果静态数据源或动态数据生成逻辑发生了更改，版本将会更新，从而允许你在沿用旧版本和使用最新版本之间进行选择。

你可以升级到最新的 `drizzle-seed` 版本以获取新功能，例如更多生成器，同时在需要时仍可使用旧版本来维持确定性的输出。这在你需要依赖现有确定性数据，同时又想使用新功能时尤其有用。

```ts
await seed(db, schema, { version: '2' });
```

<Callout collapsed="底层是如何工作的？">
> 这并不是一次真正的 API 变更；这只是一个示例，用来说明我们将如何推进 `drizzle-seed` 的版本管理。

例如，`lastName` 生成器发生了变化，并且该生成器的新版本 `V2` 变得可用。

后来，`firstName` 生成器发生了变化，使得该生成器的 `V3` 版本变得可用。

|                  |       `V1`       |      `V2`       |   `V3(latest)`   |
| :--------------: | :--------------: | :-------------: | :--------------: |
| **LastNameGen**  | `LastNameGenV1`  | `LastNameGenV2` |                  |
| **FirstNameGen** | `FirstNameGenV1` |                 | `FirstNameGenV3` |

##### 使用 3 版的 `firstName` 生成器和 2 版的 `lastName` 生成器
```ts
await seed(db, schema);
```

如果你还不想立即使用最新版本的生成器，可以指定要使用的最高版本

##### 使用 1 版的 `firstName` 生成器和 2 版的 `lastName` 生成器
```ts
await seed(db, schema, { version: '2' });
```

##### 使用 1 版的 `firstName` 生成器和 1 版的 `lastName` 生成器。
```ts
await seed(db, schema, { version: '1' });
```

</Callout>

## 版本 2
#### 唯一 `interval` 生成器已更改

<Callout title='升级原因'>
旧版生成器可能会生成像 `1 minute 60 seconds` 和 `2 minutes 0 seconds` 这样的间隔，并将它们视为不同的间隔。
然而，当 `1 minute 60 seconds` 间隔插入 CockroachDB 数据库时，它会自动转换为 `2 minutes 0 seconds`。因此，之后尝试将 `2 minutes 0 seconds` 间隔插入唯一列时会导致错误
</Callout>

如果你的表包含一个类型为 `interval` 的唯一列，你会受到影响：

```ts
import { drizzle } from "drizzle-orm/cockroach";
import { cockroachTable, interval } from "drizzle-orm/cockroach-core";
import { seed } from "drizzle-seed";

const intervals = cockroachTable("intervals", {
    interval: interval().unique()
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { intervals });
}

main();
```

如果你在种子脚本中使用唯一的 `interval` 生成器，你会受到影响，如下所示：

```ts
import { drizzle } from "drizzle-orm/cockroach";
import { cockroachTable, interval, char, varchar, text } from "drizzle-orm/cockroach-core";
import { seed } from "drizzle-seed";

const intervals = cockroachTable("intervals", {
    interval: interval().unique(),
    interval1: interval(),
    interval2: char({ length: 256 }).unique(),
    interval3: char({ length: 256 }),
    interval4: varchar().unique(),
    interval5: varchar(),
    interval6: text().unique(),
    interval7: text(),
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { intervals }).refine((f) => ({
    intervals: {
        columns: {
            interval: f.interval({ isUnique: true }),
            interval1: f.interval({ isUnique: true }),
            interval2: f.interval({ isUnique: true }),
            interval3: f.interval({ isUnique: true }),
            interval4: f.interval({ isUnique: true }),
            interval5: f.interval({ isUnique: true }),
            interval6: f.interval({ isUnique: true }),
            interval7: f.interval({ isUnique: true }),
        }
    }
  }));
}

main();
```

#### `string` 生成器已更改：非唯一和唯一均已更改

<Callout title='升级原因'>
可以根据文本列的长度生成唯一字符串（例如，`varchar(20)`）
</Callout>

如果你的表包含带有最大长度参数的类文本类型列，或者包含类文本类型的唯一列，你会受到影响：

```ts
import { drizzle } from "drizzle-orm/cockroach";
import { cockroachTable, char, varchar, text } from "drizzle-orm/cockroach-core";
import { seed } from "drizzle-seed";

const strings = cockroachTable("strings", {
    string2: char({ length: 256 }).unique(),
    string3: char({ length: 256 }),
    string4: varchar().unique(),
    string5: varchar({ length: 256 }).unique(),
    string6: varchar({ length: 256 }),
    string7: text().unique(),
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { strings });
}

main();
```

如果你在种子脚本中使用 `string` 生成器，你会受到影响，如下所示：

```ts
import { drizzle } from "drizzle-orm/cockroach";
import { cockroachTable, char, varchar, text } from "drizzle-orm/cockroach-core";
import { seed } from "drizzle-seed";

const strings = cockroachTable("strings", {
    string1: char({ length: 256 }).unique(),
    string2: char({ length: 256 }),
    string3: char({ length: 256 }),
    string4: varchar(),
    string5: varchar().unique(),
    string6: varchar({ length: 256 }).unique(),
    string7: varchar({ length: 256 }),
    string8: varchar({ length: 256 }),
    string9: text().unique(),
    string10: text(),
});

async function main() {
  const db = drizzle(process.env.DATABASE_URL!);

  await seed(db, { strings }).refine((f) => ({
    strings: {
        columns: {
            string1: f.string({ isUnique: true }),
            string2: f.string(),
            string3: f.string({ isUnique: true }),
            string4: f.string({ isUnique: true }),
            string5: f.string({ isUnique: true }),
            string6: f.string({ isUnique: true }),
            string7: f.string(),
            string8: f.string({ isUnique: true }),
            string9: f.string({ isUnique: true }),
            string10: f.string({ isUnique: true }),
        }
    }
  }));
}

main();
```

## 版本 3
#### `哈希生成函数已更改`

<Callout title='升级原因'>
之前版本的哈希生成函数会根据使用的是 Bun 还是 Node.js 生成不同的哈希，而且哈希在不同版本的 Node.js 之间也会有所不同。

新的哈希生成函数无论 Node.js 或 Bun 的版本如何，都会生成相同的哈希，从而在所有版本中实现确定性的数据生成。
</Callout>

所有生成器的输出都将与之前版本不同，即使使用相同的种子编号也是如此。

**用法**
```ts
await seed(db, schema);
// or explicit
await seed(db, schema, { version: '3' });
```

**切换到旧版本**

之前版本的哈希生成函数是 v1。
```ts
await seed(db, schema, { version: '1' });
```
要在保持 v1 哈希生成函数的同时使用 v2 生成器：
```ts
await seed(db, schema, { version: '2' });
```

## 版本 4
#### `uuid` 生成器已更改

<Callout title='升级原因'>
旧版本的 `uuid` 生成器生成的 UUID 值无法通过 Zod 的 v4 UUID 校验。

example
```ts
import { createSelectSchema } from 'drizzle-zod';
import { seed } from 'drizzle-seed';

await seed(db, { uuidTest: schema.uuidTest }, { count: 1 }).refine((funcs) => ({
		uuidTest: {
			columns: {
				col1: funcs.uuid()
			}
		}
	})
);

const uuidSelectSchema = createSelectSchema(schema.uuidTest);
const res = await db.select().from(schema.uuidTest);
// 当使用旧版本的 uuid 生成器时，下面这一行会抛出错误
uuidSelectSchema.parse(res[0]);
```
</Callout>

**用法**
```ts
await seed(db, schema);
// 或显式指定
await seed(db, schema, { version: '4' });
```

**切换到旧版本**

之前版本的 `uuid` 生成器是 v1。
```ts
await seed(db, schema, { version: '1' });
```
要在保持 v1 `uuid` 生成器的同时使用 v2 生成器：
```ts
await seed(db, schema, { version: '2' });
```
要在保持 v1 `uuid` 生成器的同时使用 v3 生成器：
```ts
await seed(db, schema, { version: '3' });
```
