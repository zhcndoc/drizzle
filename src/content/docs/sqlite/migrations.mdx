# Drizzle 迁移基础

SQL 数据库要求你先为将要存储的实体指定一个**严格的 schema**，并且如果（当）你需要改变这些实体的结构时，就需要通过**schema 迁移**来完成。

管理数据库迁移有多种适用于生产环境的方式。  
Drizzle 的设计目标是完美适配所有这些方式，无论你采用的是**database first**还是**codebase first**。

**Database first** 是指你的数据库 schema 是事实来源。你要么直接在数据库上管理 schema，要么通过数据库迁移工具管理，然后再把数据库 schema 拉取到代码库中的应用层实体。

**Codebase first** 是指你代码库中的数据库 schema 是事实来源，并受版本控制。你在 JavaScript/TypeScript 中声明和管理数据库 schema，然后再通过 Drizzle、直接操作或借助外部迁移工具把这个 schema 应用到数据库本身。

#### Drizzle 能如何帮助？
我们构建了 [**drizzle-kit**](/docs/sqlite/kit-overview)——一个用于使用 Drizzle 管理迁移的 CLI 应用。 
```shell
drizzle-kit migrate
drizzle-kit generate
drizzle-kit push
drizzle-kit pull
drizzle-kit export
```
它的设计目标是让你可以根据当前业务需求选择迁移方式。

它同时适用于 database first 和 codebase first 两种方式，支持你**推送 schema**、**生成 SQL migration** 文件，或者**从数据库拉取 schema**。  
无论你是单人开发还是团队协作，它都很适合。

<rem/>

<Tag style="font-size: 12px">**选项 1**</Tag>
> 我使用外部迁移工具或直接在数据库上运行 SQL migrations 自己管理数据库 schema。
> 对于 Drizzle，我只需要从数据库中获取当前 schema 状态，并将其保存为 TypeScript schema 文件。

<Callout collapsed="展开详情">
这是一个 **database first** 的方式。你的数据库 schema 是**事实来源**，而  
Drizzle 允许你使用 [`drizzle-kit pull`](/docs/sqlite/drizzle-kit-pull) 命令将数据库 schema 拉取到 TypeScript。

<Section>
```
                                  ┌────────────────────────┐      ┌───────────────────────────────────────┐ 
                                  │                        │ <---  CREATE TABLE `users` (
┌──────────────────────────┐      │                        │        `id` integer primary key autoincrement,
│ ~ drizzle-kit pull       │      │                        │        `name` TEXT,
└─┬────────────────────────┘      │        DATABASE        │        `email` TEXT UNIQUE
  │                               │                        │       );
  └ 拉取数据库 schema -------> │                        │
  ┌ 生成 Drizzle            <----- │                        │
  │ schema TypeScript 文件        └────────────────────────┘
  │
  v
```
```typescript
import * as p from "drizzle-orm/sqlite-core";

export const users = p.sqliteTable("users", {
	id: p.integer().primaryKey({ autoIncrement: true }),
	name: p.text(),
	email: p.text().unique(),
});
```
</Section>

<Tag style="font-size: 12px">**选项 2**</Tag>
> 我想把数据库 schema 放在我的 TypeScript 代码库里， 
> 我不想处理 SQL migration 文件。  
> 我希望 Drizzle 直接把我的 schema “push” 到数据库

<Callout collapsed="展开详情">
这是一个 **codebase first** 的方式。你的 TypeScript Drizzle schema 是**事实来源**，而  
Drizzle 允许你使用 [`drizzle-kit push`](/docs/sqlite/drizzle-kit-push) 命令将 schema 变更推送到数据库。

这是快速原型开发的最佳方式，我们看到许多团队和独立开发者  
都成功将其作为生产应用中的主要迁移流程。

<Section>
```typescript {6} filename="src/schema.ts"
import * as p from "drizzle-orm/sqlite-core";

export const users = p.sqliteTable("users", {
  id: p.integer().primaryKey({ autoIncrement: true }),
  name: p.text(),
  email: p.text(), // <--- 新增列
});
```
```

  │

  └ 拉取当前数据库 schema -----------------> │                          │
                                              │                          │
  ┌ 基于 diff 生成变更 <-------------------- │         DATABASE         │
  │                                           │                          │

                                       │      └──────────────────────────┘
                                       │
  ┌────────────────────────────────────┴─┐
   ALTER TABLE `users` ADD `email` text;
```

<Tag style="font-size: 12px">**选项 3**</Tag>

> 我希望 Drizzle 为我生成 SQL migration 文件，并把它们应用到我的数据库

```typescript filename="src/schema.ts"
  id: p.integer().primaryKey({ autoIncrement: true }),

  email: p.text().unique(),
});
```
```

│ $ drizzle-kit generate │

  │                                           
  └ 1. 读取之前的 migration 文件夹
    2. 找出当前 schema 与之前 schema 的差异
    3. 如有必要，提示开发者进行重命名
  ┌ 4. 生成 SQL migration 并持久化为文件
  │    ┌─┴───────────────────────────────────────┐  
  │      📂 drizzle       
  │      └ 📂 20242409125510_premium_mister_fear

  │        └ 📜 migration.sql
  v
```

<Tag style="font-size: 12px">**选项 4**</Tag>
> 我想把数据库 schema 放在我的 TypeScript 代码库里，
> 我希望 Drizzle 为我生成 SQL migration 文件，并且让我在运行时应用它们

<Callout collapsed="展开详情">
这是一个 **codebase first** 的方式。你的 TypeScript Drizzle schema 是事实来源，  
Drizzle 允许你使用 [`drizzle-kit generate`](/docs/sqlite/drizzle-kit-generate) 基于 schema 变更生成 SQL migration 文件，然后  
你可以在应用运行时将它们应用到数据库中。

这种方式广泛用于**单体**应用：在零停机部署期间应用数据库迁移，并在出错时回滚 DDL 变更。  
它也用于 **serverless** 部署，在部署流程中通过 **custom resource** 仅运行一次迁移。

<Section>

```typescript filename="src/schema.ts"
import * as p from "drizzle-orm/sqlite-core";

  name: p.text(),
  email: p.text().unique(),
});
```

```                                  
└─┬──────────────────────┘                  
  │                                           
  └ 1. 读取之前的 migration 文件夹
    2. 找出当前 schema 与之前 schema 的差异
    3. 如有必要，提示开发者进行重命名
```
